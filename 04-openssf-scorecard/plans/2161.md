## 四種情況分開

1. 已刪除的 release branch。raw check 對 release 的 `GetBranch` 若回錯，整個 check 回傳錯誤。後面雖然有「branch 不存在就 continue」的註解，但錯誤返回在那一行之前。這不是「未保護」的分數。
2. 改名的 default branch。`branchRedirect` 只處理 `master` 到 `main`。其他改名沒有在這份 raw check 裡辨認。
3. API 權限不足。`GetDefaultBranch` 或 `GetBranch` 的錯誤會讓 raw check 失敗。這是 check 錯誤，不是 unprotected 分數。
4. 真正未保護。evaluation 在拿得到 probe、而且分數落到最低分時，才是 protection 沒開啟。`#5455` 另外把 unknown 從這條路拆出去，維持 inconclusive。

`unknown` 與 `unprotected` 不要合成同一個結果。可控的預期行為只先寫第 1 種：已刪除的 release branch 不應被記成未保護。分數要不要因此變，等維護者同意。

## 測試現況

`main` 的 raw 測試把 `default-branch-err` 與 `release-branch-err` 都預期成 check 錯誤。`master-to-main-redirect` 是測試裡看得到的改名案例。evaluation 測試在 `main` 上是各層保護組合的分數，沒有把已刪除 release branch 從 unprotected 拆出來。`#5455` 才在 PR diff 加上 unknown 不計分的案例，那是 `#5450`。
