# trivy-action #551 設計筆記

last_verified_at：`2026-11-13T16:55:05Z`

狀態維持 `NEEDS_MAINTAINER`。這是設計對照，不是實作。只使用 `gh api` GET。

## 現況下載路徑

`aquasecurity/trivy-action` 的 `entrypoint.sh` blob `f0fbfb45f45abc8b8e1d87527ffb3d980f2cf2e3` 只執行已經在 PATH 上的 `trivy`，不下載二進位。

`action.yaml` blob `612a3a566101a33dd4599f5b8ca6372819c22459` 在 `skip-setup-trivy` 為 false 時呼叫 `aquasecurity/setup-trivy`，pin 在 commit `81e514348e19b6112ce2a7e3ecbafe19c1e1f567`。它把 `version` 與 `cache` 傳過去，沒有 `sha256` 輸入。DB cache 是另一條 `actions/cache`，不是二進位簽章。

`setup-trivy` `main` 的 `action.yaml` blob `20f4b93b77109dfcbad1d0d70b41398bb039abd7` 在 cache miss 時 checkout `contrib/install.sh` 再安裝。cache key 含 version、OS、arch。`latest` 不進 cache。

## #40 與 #43

兩者都只改 `setup-trivy` 的 `action.yaml`。

`#40` 仍 OPEN。diff 改成從 release archive 取 tarball，依 OS/arch（含 Linux ARM64）選資產，並用發布的 `checksums.txt` 跑 `sha256sum -c`。抽樣的新增行沒有簽章驗證。

`#43` 是 closed unmerged。同樣改走 release archive 與 checksum，並寫到避開 `get.trivy.dev` 的 curl 失敗。也沒有在抽樣行看到簽章。

所以 `#551` 對這兩個 PR 維持 `possible_overlap`：它們改的是安裝來源與 checksum，不是已經在 `trivy-action` 落地的功能，也還沒有簽章。

## 功能該放哪裡

二進位的版本釘選、SHA-256、架構與 cache 目前都在 `setup-trivy`。`trivy-action` 只負責把 version 傳進去並執行掃描。checksum 若要做，應由維護者決定是併進 `#40` 這條安裝路徑，還是另開 `setup-trivy` 的 issue。不在 `trivy-action` 再做一個下載器，也不把需求改送到 `trivy-db`。

簽章與發布流程這兩項，這次讀到的 diff 沒有涵蓋。沒有維護者同意之前，維持 `NEEDS_MAINTAINER`。
